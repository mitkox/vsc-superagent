# Security and enterprise deployment

The extension contains no analytics, telemetry API, tracing exporter, remote logger, background updater, model SDK or HTTP listener. Its network calls are explicit source reads. Copilot model requests are made by VS Code/Copilot when the user runs the native agent, under the organization's Copilot policies. GitHub and Graph still receive authenticated API requests. A cloud Copilot workflow cannot provide a guarantee of zero provider-side operational logging or zero data egress.

The extension requires `telemetry.telemetryLevel=off` and `vscode.env.isTelemetryEnabled=false` before providing its work tools. It also rejects enabled Copilot/Agent Host OpenTelemetry exporters, Copilot debug file logging (including the legacy `chatDebug.fileLogging.enabled` key; `agentDebugLog.fileLogging.enabled` must be explicitly `false` because experiments can enable it) and nonempty `COPILOT_OTEL_*` / `OTEL_*` environment overrides (except values that disable export: `OTEL_SDK_DISABLED=true`, `COPILOT_OTEL_FILE_EXPORTER_PATH` set to the null device, and `false`/`0` for `COPILOT_OTEL_ENABLED`, `COPILOT_OTEL_CAPTURE_IDENTITY` and `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`). The error names each active setting or variable, never its value. These exporters are separate from product telemetry. If they were enabled at extension startup, a reload is required after disabling them. The privacy command changes user settings only after explicit consent. This cannot control telemetry from other installed extensions, Microsoft sign-in, Copilot services, GitHub, Graph, or native tools selected by the user. Manage those independently under enterprise policy. If zero third-party collection or offline execution is mandatory, cloud Copilot cannot meet that requirement.

## Enforced boundaries

- Workspace Trust, one file-backed repository, and telemetry checks run before operations and after interactive waits. Configuration is application-scoped. Models and repository files cannot change the extension's source scope.
- Remote messages require sender and source allowlists, then a native local decision. Remote text is displayed as plain text and grants no authority. No LLM decides admission.
- Teams uses tenant-scoped Microsoft authentication and a fixed Graph origin. GitHub secrets are scoped to the exact configured API origin/repository. HTTPS, no redirects, exact-path pagination, cancellation, response/time/page limits and sanitized failures protect credentials. TLS verification is never disabled.
- Worktrees are created with argument arrays and no shell. Git environment injection, hooks, fsmonitor, submodule recursion, external protocols and smudge/process filters are disabled during preparation. Committed primary HEAD is used; unrelated dirty files are not copied, reset or cleaned. No remote Git operation is performed by the extension.
- Ticket state commits synchronously through private temporary files, file fsync, atomic replacement, checksums and an exclusive lock. Corrupt state is preserved. Interrupted active work requires local retry. No external side effect is replayed at startup.
- The extension provides no API for sending messages, pushing, merging, deploying, running arbitrary commands, reading credentials or changing system security settings. Local mutation tools require native confirmation in addition to Copilot's tool confirmation.

## Boundaries owned by VS Code and your organization

Native Copilot edit/terminal tools run under VS Code's permissions and sandbox, not a sandbox implemented by this extension. Agent instructions guide behavior; they are not an enforcement boundary. A user can select another agent, add tools or change instructions. Pausing/stopping a ticket does not kill already-running native Copilot tools. Use Chat Stop and organizational controls. Do not enable blanket tool auto-approval or permission bypass. Use managed workstations/containers and network policy for actual execution isolation. Treat repository code, build scripts, dependencies and Git worktrees as executable, untrusted inputs even after ticket approval.

Configure GitHub branch protection, required independent review, dismissed stale approvals, protected deployment environments and least-privilege credentials server-side. A progress report cannot prove these controls passed. Source read allowlists narrow this extension's requests, but delegated Graph consent may authorize broader reads by the authentication application; administrators must assess that permission boundary. Teams message content becomes Copilot context only after local approval; apply your information classification and Copilot data policies before approving it.

POSIX private modes protect local state from other ordinary OS users. This is not encryption, protection from the same OS identity, proof against a compromised extension host, or a tamper-evident compliance ledger. Use encrypted disks, enterprise ACLs, approved credential storage, retention/backup procedures, and centralized audit systems if required. No credentials should be placed in ticket text. Secrets intentionally pasted into an approved task may become part of local state or Copilot context.

## Qualification before production rollout

1. Build from the pinned lockfile in controlled CI; run typecheck, all behavioral/security tests, production dependency audit, package checks, and inspect the VSIX inventory/hash. Review development dependency advisories and sign/distribute the approved artifact through your organization's extension process. The local publisher name is not a signing identity.
2. Install on the exact supported VS Code, Copilot and OS/remote-host versions. Verify agent/tool discovery, user consent, no automatic work on activation, cancellation, restart/retry, private storage, worktree switching, and error recovery. The isolated native smoke test in `scripts/editor-smoke.cjs` verifies discovery, activation and tool registration on Insiders 1.145; it does not prove a live Copilot workflow or tenant acceptance.
3. Have your Entra administrator approve delegated Graph permissions for the sign-in application. Test allowed and denied tenants, senders, chats, channels, pagination, expired/revoked consent and conditional-access policies against a test tenant. Verify that no messages are sent. National clouds need an explicitly reviewed implementation.
4. Test GitHub/GHES read permissions, exact repository binding, token rotation/revocation, rate limits, PR completion readback and source scope changes. Use representative history sizes: bounded scan limits are deliberate blockers, not a scale qualification.
5. Independently inspect outbound traffic during activation, local ticket work, polling and model use. Distinguish extension source API traffic, Copilot inference, platform telemetry and provider operational logs. Establish the organization's acceptable data and retention policy.

Report security findings privately to your deployment's maintainers. Never include live tokens, private ticket text, or confidential Teams content in public bug reports.
