# Security and deployment boundaries

Superagent uses the shared ticket engine and the official Copilot SDK through an installed Copilot CLI over stdio. It polls configured GitHub/Teams sources, launches authorized coding sessions and sends replies when explicitly enabled. It has no extension telemetry exporter, HTTP listener or automatic updater. Copilot inference and provider operational logging remain governed by their services and organization policies.

## Authorization and execution

Workspace Trust, one file-backed repository, privacy checks and application-scoped source configuration are required. Provider/model text cannot change settings or credentials. Continuous execution and source sending start after native operator setup. Allowed explicit requests grant immutable bounded mandates; proactive work additionally requires an enabled acceptance mode and matching rules. Bots/CI provide context, never explicit authority.

Operators choose confirmation for each worker permission or execution within approved ticket mandates. Unattended shell commands run as the operator and can invoke programs, Git and network clients. Worktrees isolate changes, not privileges; use an OS/container sandbox and network policy for actual isolation. Ticket mode is a native task-level grant, not proof that each shell command originated from admitted text. Reported shell paths/URLs are advisory and may omit accesses; they do not enforce filesystem or network confinement. Disabling built-in source replies does not restrict CLI programs. Managed approvals and sandbox bypasses remain interactive. Late approvals are rejected after cancellation. Pause/stop/revocation withdraw future custom-tool authority and request native worker abort.

Ready means human review requested, not CI, independent approval, merge, deployment or acceptance. PR binding verifies the source PR or configured agent's exact ticket branch. Auto-merge requires a separately configured merge CLI and delivery conditions. Server-side branch protection, independent review and protected deployment environments remain authoritative.

## Source boundaries

GitHub credentials use SecretStorage bound to exact origin/repository. Graph credentials come from tenant-pinned Microsoft authentication. Tokens are supplied afresh and not persisted in ticket state. HTTPS, locally constructed fixed/configured paths, no redirects, exact-path pagination, cancellation and response/page limits constrain provider requests.

Teams sends require delegated Graph scopes and target the original message. `/me` identifies the authenticated sender so its messages are excluded. Full context retains native IDs, URLs, review roots, file/line positions and quote references. External text is rendered as plaintext and passed as untrusted model context. Core gates restrict replies to reached conversations; context subscriptions grant no writing authority. Review resolution verifies the exact repository/PR thread. Source sending and CLI publishing have separate permission/credential boundaries.

Unlisted-addressed `explicit` is an intentional operator-selected sender grant, not an allowlist exception inferred from a message. It permits anyone in the receiving scope to originate work in every proactive mode. Defaults ignore unlisted senders. The legacy family admission table applies to all current and future configured scopes; optional tenant/repository-bound `admissionByScope` rows can narrow individual receiving scopes. Producer namespace and native receiving metadata determine a row, never message text or a claimed row label.

Native requester, bot, enabled and observation changes apply immediately to the corresponding policy field; unchanged native fields preserve dashboard overrides. Per-field applied fingerprints survive reopen, and native configuration events, setup and polling share the same partial reconciliation. Permission checks project pending native changes without writing state. Legacy global fingerprints seed the new baseline unchanged when they match, or recover it from hash-proved settings history. If no baseline can be proved, one conservative migration narrows lists/switches against current native values; review old overrides before restoring them. Admission tables, scoped rows, rules and source history are preserved.

Changing the native GitHub origin/repository or removing a Teams tenant/conversation withdraws source-derived execution, including active tool and permission requests. Equivalent canonical identities and added scopes retain existing grants. Unprovable historical provider scope fails closed; retained source history is preserved. Native-approved local imports retain their separate execution grant, but provider writes still require their original exact destination to be currently configured. Unprovable legacy scope cannot evade a newly narrowing scoped policy. Removing an allowlist entry alone does not exclude someone whom another admission grant still admits.

Native Save/Restore confirmation names newly broadened unlisted classes and configured scopes, including dormant grants, effective activation and a removed narrowing row. The host freezes the validated candidate, then rechecks revision and native receiving scope/permission mode after consent. Policy/source text and worker tools cannot invoke that native settings action. Settings and Start disclose persisted grants; existing family grants are not silently migrated or invalidated, and background polling does not display consent prompts. Current policy and immutable mandate revalidation still withdraw future inputs/tools when a grant weakens. These confirmations grant policy admission, not new credentials or operating-system isolation.

Subscriptions retain source history; they do not admit senders. Current policy is checked before automatic fan-out, assessment and worker dispatch. Unadmitted participant text remains available through explicit authorized history reads, but does not wake a worker or grant acknowledgement, answer or review-resolution authority. Retired operational inputs remain passive across retry and reopen. Explicit ignore cells apply to participating users too. Native imports approved by the operator retain their local authorization.

Inferred requests require the configured acceptance mode and enabled matching rules; they cannot borrow explicit authority by sharing an assessment batch. Automatic assessments group only requests from the same sender and receiving-row grant. Previously accepted mixed-origin scopes fail current execution checks rather than silently dropping a contributor from their immutable scope; the source history remains available. Restoring allowlists does not repair a mixed scope: stop the old ticket and submit fresh requests separately under each grant rather than rewriting the old mandate. Assessed configured-bot feedback returns to an existing subscribed ticket under its unchanged mandate. Authenticated PR CI readback has a separate durable receipt bound to the exact event/head, source and existing ticket mandate. A scoped default-branch CI opt-in uses its own normalized event/repository/branch/head receipt and remains inferred and rule-gated. Subsequent verified facts update the same live CI mandate and receiving branch. A fact after completion requires a fresh inferred assessment and cannot resume the ended ticket; raw bot messages do not create this provenance. A body, sender-type flag or `meta.ci` field cannot create that receipt. Check names/output and explicitly read history remain untrusted data. These controls prevent passive messages from triggering work; they do not eliminate prompt injection through files, history or persistent model context, and do not replace a sandbox.

Messages are persisted before dispatch. Authenticated receipt markers reconcile uncertain sends. Missing receipts do not prove non-delivery; the service keeps an actionable failure rather than repeating the POST. This is safe reconciliation, not a universal exactly-once provider guarantee.

## State and recovery

State is namespaced by canonical Git common directory. POSIX files/directories use private modes. Checksums, fsync, atomic replacement and exclusive writer ownership protect durable records. Events and cursor advancement share a transaction. Assignments, sessions, inputs, policy/prompt revisions and operations survive restart; workers retain their worktrees and conversation identities.

State includes provider text and local session transcripts. Streamed supervision diagnostics are coalesced on a short timer and drained on worker termination and service stop. Pending diagnostics share a 2 MiB/2,000-event buffer, with at most 500 per session; pressure may trim its oldest entries. Abrupt process termination can lose the recent unflushed diagnostic tail. Source messages, mandates, reports and effects still commit durably without this delay. Supervision transcripts retain a bounded diagnostic tail shared across sessions and may be pruned before a commit to make room for business records; source history, mandates, settings and operations are not pruned by this retention policy. It is not encrypted or an immutable compliance ledger, and does not protect against the same OS user or a compromised extension host. Use encrypted storage, OS ACLs, retention controls and backups. Do not place secrets in ticket text. Copilot's own persistent session store is separate. Windows mode bits do not establish ACL isolation.

Closing the workspace extension host stops its service; an enabled service resumes on reopening. Corruption and uncertain lock ownership fail closed. Preserve state and verify owner processes before manual recovery; never reset unrelated checkouts or delete worktrees to recover a ticket.

Automatic lock recovery requires a confirmed dead PID on the same host and serializes reclamation with acquisition. A leftover `state.lock.acquire` guard is deliberately not reclaimed without inspection. PID reuse or inaccessible owner state preserves the lock.

## Privacy and rollout qualification

Local checks cover product telemetry, known Copilot/Agent Host exporters and debug logging. Apply Local Privacy Settings changes user settings only after native confirmation; startup-active exporters require reload after disabling. The SDK child disables known exporter variables. Other extensions, Microsoft sign-in, Copilot, GitHub, Graph and native tools remain separate logging boundaries. Cloud model execution includes data egress.

Before rollout, build from the lockfile, run checks/audits, inspect the VSIX/hash, and sign/distribute through the approved extension process. Validate exact editor/CLI/OS versions, allowed/denied tenants and senders, replies, revoked credentials, conditional access, pagination, cancellation and crash recovery in a test repository/tenant. Inspect traffic and classify source/model data. Fixtures and registration smoke tests do not qualify tenant access, scale or release readiness.

Report security findings privately to deployment maintainers; never post tokens or confidential source/ticket content publicly.
